# 按需读取验证记录

2026-11-16：当前实现采用单文件按需读取。此处记录合成数据的本地验证范围；最新远程CI、自动审查、部署及生产HTTP结果以对应PR交付报告为准。

| 验证              | 证据与范围                                                                                                                                                            |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 发布契约          | 保留Schema v1、严格JSON/重复键/排序/四件套/版本、每文件及Manifest大小约束；遵循发布者1000组上限，取消网关8组/总产物8MB限制                                            |
| REST集合          | 三个客户端的Bearer/URL列表、无凭据回显、尾斜线、范围/停用过滤、空列表、按设备计算ETag、HEAD/304前重新认证、更新/删除跟随；冷3次/热1次，只读元数据，不破坏最近文件缓存 |
| 按需读取          | 只读取Manifest与目标文件正文；冷读取4次、同版本换文件2次、同文件命中缓存1次；1000组合成仓库仍为4次冷调用，最近文件字节缓存不会随路径增长                              |
| 完整性与隔离      | 绑定同一dist SHA；Manifest和目标路径Git mode检查，拒绝symlink/submodule、截断/超限/重复树元数据；目标文件大小/SHA不符则拒绝，未请求正文缺失或损坏不阻断当前下载       |
| 更新与删除        | 读取期间dist更新不混用版本；每次重新解析ref；删除后404，刷新失败503，不从旧缓存补齐                                                                                   |
| HTTP与鉴权        | health、401/403/410、Token撤销、独立URL模式、精确路径与仓库范围授权、HEAD/304前鉴权、四类MIME和二进制字节、安全头与日志脱敏                                           |
| 官方Workers运行时 | @cloudflare/vitest-plugin在workerd运行，覆盖实际生产入口和原生fetch出站（固定GitHub网络边界的合成模拟）                                                               |
| 上游故障          | 模拟401/403/404/429/5xx、无dist、重定向、非法Contents/Base64、请求与body超时、单文件总时限、Retry-After退避                                                           |
| 规模              | 9组合成规则声明36MB总产物时，只下载并校验所请求的1MB文件；1000组成功读取一个文件；1001组在产物读取前拒绝。不是生产CPU或并发压测                                       |
| 工程检查          | bun run check、bun audit、cf生成类型与构建检查、git diff --check；最终结果以当前PR/交付报告为准                                                                       |
